2. Typography Hierarchy
System stack: Segoe UI → system-ui → -apple-system. Scale follows a 1.25 modular ratio for coherent hierarchy. Min 16px body text for readability.
Display — Page Title 36px / 800
Heading 1 — Section 28px / 700
Heading 2 — Card Title 22px / 700
Heading 3 — Sub-section 18px / 600
Body Large — Primary content 16px / 500
Body — Table cells, form labels 14px / 400. The quick brown fox jumps over the lazy dog.
Body Small — Helper text, captions 13px / 400. Used for secondary metadata.
Overline — Table headers, labels 11px / 600 UPPERCASE
Mono — Reference IDs, codes, system values 13px
⚠️ Accessibility Rules
  • Never use font-size below 12px (13px minimum for non-decorative text)
  • Body text minimum 16px for paragraph content — improves literacy for elderly residents
  • Line-height minimum 1.5 for body text (WCAG 1.4.8)
  • Letter-spacing at least 0.12× font-size for body text
  • Avoid italics for text longer than one sentence
3. Status Badges — Request Tracking
Used across all request/ticket tracking. Color-coded with an accessible indicator dot and text label (never color alone — WCAG 1.4.1).
Pending Processing Approved Rejected Escalated Completed
Usage rule: Each badge uses a colored dot + colored text on a matching light background. Screen-reader text includes status label via aria-label. Example: <span class="badge badge-pending" aria-label="Status: Pending">
4. Button System & Permission Gates
Seven button variants. Permission-gated buttons are visually distinct (dashed amber border) and show a tooltip explaining why access is restricted.
Permission gate rule: When a user's role lacks permission, buttons render as 🔒 gated style with a tooltip. They are focusable but non-clickable (aria-disabled). This prevents "hidden elements" that disorient screen readers.
5. Notification Banners
System-wide alerts, inline form validation notices, and contextual guidance. Auto-dismiss with countdown for non-critical types.

All inputs have visible focus rings (3px solid primary — WCAG 2.4.7), error states, helper text, and associated labels (WCAG 1.3.1). Modal forms use a persistent overlay trap.

8. WCAG AA Accessibility Guidelines
All components are designed to meet WCAG 2.1 Level AA. The following checklist should be validated before shipping any new component.
✅ Perceivable
✓ 4.5:1 minimum contrast for normal text (1.4.3)
✓ 3:1 minimum contrast for large text & UI (1.4.11)
✓ Status never conveyed by color alone — use icon + label (1.4.1)
✓ All images have alt text; decorative images alt="" (1.1.1)
✓ Form labels programmatically associated (1.3.1)
✓ Focus order is logical (1.3.2)
✓ Text resizable to 200% without loss of content (1.4.4)
✅ Operable & Understandable
✓ All interactive elements keyboard-accessible (2.1.1)
✓ Visible focus indicator — 3px solid primary (2.4.7)
✓ Skip navigation link at page top (2.4.1)
✓ Descriptive link text — no "click here" (2.4.6)
✓ Error messages identify field and suggest correction (3.3.3)
✓ Language identified in HTML lang attribute (3.1.1)
✓ Modal dialogs trap focus and restore on close (2.1.2)
✓ Timeout warnings with extension option (2.2.1)
